# 图片全局预览与自动落盘设计文档

## 1. 目标

在现有 GPT Image-2 对话式图像工作台基础上，补齐图片结果的查看与保存链路，使生成结果不再只是消息流中的一张图，而是具备完整的预览、下载和本地落盘能力。

本次增量设计目标如下：

- 点击任意生成图后，可进入沉浸式全局预览。
- 同一批次生成多张图时，支持在预览层中切换。
- 每次生成成功后，自动触发浏览器下载。
- 同时预留并实现一个本地桥接能力，将图片写入项目内固定目录。
- 聊天框下方的参数选择器全部改为组件形式，禁止使用原生 `select`。

## 2. 范围

### 2.1 必须完成

- 全局预览层。
- 浏览器自动下载。
- 本地桥接服务与项目目录落盘。
- 图片卡片点击打开预览。
- 输入区底部参数切换为 Naive UI 组件。
- 落盘失败不阻断主生成流程。

### 2.2 建议完成

- 预览层内切换上一张与下一张。
- 预览层内显示主题名、模型名、尺寸和当前序号。
- 预览层内提供单独下载当前图动作。

### 2.3 暂不纳入

- 复杂拖拽平移。
- 自由旋转。
- 服务端图像管理后台。
- 云端图库同步。

## 3. 产品定位

本次增量不改变当前产品的“聊天式图像工作台”定位，而是补全结果层体验。

定位原则如下：

- 图片查看保持沉浸式、高质感，不做廉价弹窗。
- 保存链路保持双轨：浏览器自动下载保证开箱即用，本地桥接保证项目目录落盘。
- 组件选择器保持统一视觉，不再混入原生表单控件。

## 4. 核心方案

建议采用“前端增强 + 本地落盘桥接”的组合方案。

### 4.1 前端增强

前端负责：

- 图片卡片点击交互。
- 全局预览层显示与切换。
- 浏览器自动下载。
- 本地桥接请求发起。
- 本地桥接失败提示。

### 4.2 本地落盘桥接

本地桥接负责：

- 接收前端发来的 base64 图片数据。
- 写入项目目录中的固定文件夹。
- 返回相对路径与绝对路径。

### 4.3 为什么不用纯前端直接写项目目录

浏览器环境无法直接把文件安全写入当前项目工作区，因此“保存到项目文件夹”必须依赖本地 Node 桥接服务。

因此：

- 浏览器自动下载可作为兜底能力。
- 项目目录落盘必须通过桥接服务实现。

## 5. UI 设计

### 5.1 全局预览层

新增 `ImagePreviewModal.vue`，作为全屏图片查看层。

要求如下：

- 点击任意生成图后打开。
- 全屏遮罩，深色高模糊背景。
- 居中显示当前图片。
- ESC 可关闭。
- 点击遮罩空白区域可关闭。
- 同一批次多图支持左右切换。
- 支持滚轮缩放。

### 5.2 预览层动作区

预览层顶部或底部动作区至少包含：

- 下载当前图。
- 上一张。
- 下一张。
- 关闭。

预览层信息区显示：

- 当前主题名。
- 当前模型名。
- 当前尺寸。
- 当前序号，如 `1 / 4`。

### 5.3 聊天框下方组件约束

聊天框下方的参数选择器全部改用组件，不再允许原生 `select`。

统一约束如下：

- 模型选择使用 `n-select`
- 尺寸选择使用 `n-select`
- 张数选择使用 `n-select` 或 `n-segmented`
- 后续新增的质量、背景、压缩参数也统一走组件

目标是保证深色工作台风格的一致性和质感。

## 6. 下载与落盘链路

### 6.1 浏览器自动下载

每次生成成功后，前端自动触发下载。

文件命名规则建议：

```text
主题名-YYYYMMDD-HHmmss-01.png
主题名-YYYYMMDD-HHmmss-02.png
```

原则：

- 一次请求生成多张图时，按序号追加。
- 若主题名为空，回退到 `image-session`。
- 文件名需进行非法字符清理。

### 6.2 项目目录自动落盘

前端在生成成功后，额外调用本地桥接服务，将图片写入项目目录。

建议落盘目录：

```text
public/generated/
```

原因：

- 开发时即可直接访问。
- 后续可作为历史缩略图或图库来源。
- 不需要改动额外静态资源映射。

### 6.3 双轨策略

生成成功后执行顺序：

1. 渲染消息卡片。
2. 自动触发浏览器下载。
3. 调用本地桥接服务写盘。
4. 若桥接成功，则记录相对路径。
5. 若桥接失败，只提示失败，不影响已生成图片的展示与下载。

## 7. 本地桥接设计

### 7.1 服务文件

建议新增：

- `scripts/image-bridge.mjs`

该服务只负责一件事：接收图片数据并写入 `public/generated/`。

### 7.2 前端服务层

建议新增：

- `src/services/localImageBridge.js`

职责：

- 调用本地桥接服务。
- 传递主题名、文件名、base64 数据。
- 处理失败提示和返回路径。

### 7.3 接口定义

建议接口：

```http
POST /api/save-image
```

请求体：

```json
{
  "topicTitle": "新建创作",
  "fileName": "新建创作-20260703-224500-01.png",
  "imageBase64": "iVBORw0KGgoAAA...",
  "subDir": "generated"
}
```

返回体：

```json
{
  "success": true,
  "relativePath": "/generated/新建创作-20260703-224500-01.png",
  "absolutePath": "/Users/xxx/BrainHub/Code/Demo/ai-chat-draw/public/generated/新建创作-20260703-224500-01.png"
}
```

## 8. 数据结构增量

现有 `assistant_images` 消息需要补充本地保存相关字段。

建议新增：

```js
{
  images: [
    {
      id: 'string',
      url: 'data:image/png;base64,...',
      localPath: '/generated/xxx.png',
      savedToProject: true
    }
  ]
}
```

说明：

- `localPath` 为桥接成功后的项目相对路径。
- `savedToProject` 用于区分是否已成功写入项目目录。

## 10. 错误处理

### 10.1 预览层错误

- 某张图加载失败时显示占位提示。
- 不影响其他图片浏览。

### 10.2 浏览器下载失败

- 保留手动下载入口。
- 不影响消息卡片和预览层。

### 10.3 本地桥接失败

- 提示“图片已生成，但项目目录保存失败”
- 不影响消息展示
- 不影响浏览器自动下载
- 不影响继续细化和参考图能力

## 11. 测试策略

至少覆盖以下行为：

- 点击图片后打开全局预览层。
- 同一批次图片可左右切换。
- 生成成功后触发浏览器下载。
- 调用本地桥接时请求体符合约定。
- 本地桥接失败时主流程仍可正常显示图片。
- 输入区底部不再存在原生 `select`。

## 12. 验收标准

本次增量完成后，应满足以下标准：

- 用户点击图片可进入沉浸式全局预览。
- 同批次多图可在预览层中切换。
- 生成成功后浏览器自动下载图片。
- 图片可自动写入项目目录 `public/generated/`。
- 本地落盘失败不会影响图片查看与聊天续写。
- 输入区底部参数使用 Naive UI 组件，而不是原生选择器。

## 13. 风险与约束

- 项目目录落盘依赖本地桥接服务，纯前端无法单独完成。
- 浏览器自动下载可能被浏览器安全策略拦截，因此仍需保留手动下载入口。
- 若一次生成多张大图，自动下载和本地落盘会增加短时 I/O 压力。
- 本地桥接服务应限制写入目录，避免任意路径写盘风险。

## 14. 最终结论

本次增量应采用“沉浸式预览 + 浏览器自动下载 + 本地桥接落盘 + 统一组件选择器”的组合方案。

该方案同时满足以下目标：

- 让图片结果具备成熟 AI 工作台应有的查看体验。
- 让生成结果自动留存在用户系统和项目目录中。
- 保持当前前端聊天工作流不被本地落盘能力绑死。
- 统一输入区的交互质感，去掉原生 `select` 带来的割裂感。
